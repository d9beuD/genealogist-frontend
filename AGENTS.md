# AGENTS.md

## Stack

Nuxt 4 + Vue 3 + TypeScript + Tailwind v4 (via `@tailwindcss/vite` Vite plugin, not the classic module approach).

## Commands

```
npm install        # also runs `nuxt prepare` via postinstall
npm run dev        # dev server on localhost:3000
npm run build      # production build
npm run preview    # preview production build
npm run generate   # static generate
```

## Gotchas

- `tsconfig.json` is a reference-only shim pointing at `.nuxt/tsconfig.*.json`. **Do not edit it directly** — those files are regenerated by `nuxt prepare`.
- `.nuxt/`, `.output/`, `.data/`, `.nitro/`, `.cache/`, `dist/` are all generated. Do not commit them.
- No tests, lint, or CI are configured yet.
- Tailwind v4 is loaded as a Vite plugin in `nuxt.config.ts`, not via the old `tailwind.config.js` approach. The CSS entry is `~/assets/css/tailwind.css`.
- shadcn-vue components have **no prefix** (set `shadcn.prefix: ""` in `nuxt.config.ts` and `components.json`). Use `<Button>`, not `<UiButton>`.
- `components.json` is the source of truth for shadcn-vue CLI config (style: new-york, font: inter, baseColor: taupe, iconLibrary: lucide). The shadcn-vue MCP reads this file.
- There is a hand-rolled Nuxt module at `modules/shadcn.ts` that auto-registers component exports from `@/components/ui`. The `shadcn-nuxt` module is also registered in `nuxt.config.ts` for CLI integration — they serve different purposes.
- `~/lib/utils` exports `cn()` for class merging (clsx + tailwind-merge).

## Structure

- `app/` — Nuxt app directory (pages, components, plugins, assets, lib)
- `modules/shadcn.ts` — custom Nuxt module for component auto-registration
- `components.json` — shadcn-vue CLI configuration
- `opencode.json` — shadcn-vue MCP server config (runs `npx shadcn-vue@latest mcp`)
