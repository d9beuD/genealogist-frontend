# AGENTS.md

## Read First

- Use Deno, not Node/npm, for the repo runtime and package management.
- `package.json` is the command source of truth.
- `deno.json` is the Deno config source of truth.
- `nuxt.config.ts`, `components.json`, `modules/shadcn.ts`, and `opencode.json` define the repo-specific wiring.

## Repo Shape

- Single Nuxt 4 app with Vue 3, TypeScript, and Tailwind v4.
- App code lives under `app/`.
- `modules/shadcn.ts` auto-registers exports from `@/components/ui`; `shadcn-nuxt` is also enabled in `nuxt.config.ts` for CLI integration.

## Commands

```bash
deno install
deno task dev
deno task build
deno task preview
deno task generate
```

## Gotchas

- `deno install` runs `nuxt prepare` through `package.json` `postinstall`.
- `tsconfig.json` is generated by Nuxt and should not be edited directly.
- Do not commit generated Nuxt outputs: `.nuxt/`, `.output/`, `.data/`, `.nitro/`, `.cache/`, `dist/`.
- There is no configured test, lint, or CI workflow in the repo right now.
- Tailwind v4 is wired through `@tailwindcss/vite` in `nuxt.config.ts`; the CSS entry is `~/assets/css/tailwind.css`.
- shadcn-vue uses no prefix here. Import/use `<Button>`, not `<UiButton>`.
- `components.json` is the source of truth for shadcn-vue config and the MCP server reads it.
- `~/lib/utils` exports `cn()` for class merging.
